# 两表最小实现说明

## 1. 当前目标

只实现两个核心功能：

1. 保存、读取和删除用户当前画像。
2. 用户确认路线后，使用本次成对选择继续学习并更新当前画像。

路线推荐是即时计算，不需要保存推荐过程。

## 2. 为什么只需要两张表

### `users`

保存用户 ID、外部用户编号、初始化方式和创建时间。

### `user_profiles`

以 `user_id` 作为主键，每个用户只有一行当前画像。保存内容包括：

- 四维 Gaussian 系数；
- 4×4 协方差矩阵；
- 有效学习次数；
- 最近一次计算是否收敛；
- 创建和更新时间。

权重和百分比都能由四维系数计算，因此不落库。系数边界是算法常量，也不落库。

## 3. 学习方式

创建用户时生成默认或命名预设画像，并写入 `user_profiles`。

用户提交选中路线和对比路线后：

1. 锁定该用户的当前画像行；
2. 从两条路线提取归一化差值；
3. 把当前画像后验作为本次计算的先验；
4. 执行一次 Laplace 增量更新；
5. 用新系数、协方差和学习次数覆盖当前画像行。

所以继续学习不依赖路线历史、选择事件或证据表。

## 4. 暂不实现

- 推荐会话和路线快照；
- 画像历史版本；
- 选择事件审计与撤回；
- 异步画像更新任务和 worker；
- 幂等请求记录；
- API 鉴权。

以后只有在出现明确业务需求时，才增加对应表和功能。
