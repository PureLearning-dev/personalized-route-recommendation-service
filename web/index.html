这不是算法宣传页。它按真实源码回答：从哪里进入、依次调用谁、对象怎样变化、 哪些分支会提前返回，以及最后拿到什么。

画像不是直接计票。每次选择先转为四维差值，再通过 Laplace 贝叶斯更新后验。

推荐不负责找路。候选路线由上游服务提供；这里仅过滤、计分与重排。

JND 可能改变初排。它用可感知差异判断“谁真的更好”，不是再算一次加权和。

    画像侧

    1. RouteAttributes 调用方创建 · 四项原始代价
    2. PairwisePreference 标明 chosen / rejected
    3. FeatureComparison 内部对象 · 归一化后的四维向量

    5. PreferenceLearningResult 权重、后验、证据数、概率、收敛状态

    推荐侧

    1. RouteAttributes[] 上游路径服务生成的候选集
    2. RouteConstraints + JndThresholds 本次请求显式传入的配置
    3. RankedRoute / RejectedRoute 每条路线的计分明细或淘汰原因
    4. RouteRankingResult 保留完整加权初排，供审计与 JND 使用
    5. JndEnhancedRankingResult 最终 Top-K + 全部比较过程

    这些分支决定了“空数据、非法配置、无可行路线、数值不收敛”时程序实际会怎样结束。

    画像学习的分支

    comparisons 为空

    group_histories 非空
    先循环估计群体 MPP，KL 散度小于 0.001 才停止，再学习个人后验。learner.py:207–211 · inference.py:238–261
    五个随机起点都失败
    ProfileNumericalError；不把不可靠后验继续传给下一题。optimization.py:368–385

    路线推荐的分支

    候选为空或 route_id 重复
    RecommendationValidationError；排序没有可定义的输入。ranking.py:85–90
    一条路线违反多个约束
    全部超限维度写入 RejectedRoute，随后 continue，绝不参与计分。models.py:64–85 · ranking.py:104–108
    所有路线都被过滤
    这是有效空结果，不抛错；recommended 返回 None。ranking.py:119–125 · jnd.py:168–178
    差值恰好等于 JND 上限
    仍归入“不可明显区分”；只有 difference > limit 才出组。jnd.py:92–100

    这个仓库现在没有做的事

    读代码时最容易把“论文设想”误认为“已经实现”。以下边界在当前源码中是明确的。

    • 不搜索路径：没有交通网络图、K 最短路或多模式路径生成器。
    • 不自动学习 JND 阈值：JndThresholds 必须由调用方显式传入。
    • 不自动匹配群体：group_histories 假设上游已经选好相似用户。
    • 不接情境数据：天气、目的地、时段和实时供给尚未进入当前四维模型。
    • 不把模拟选择当真实反馈：演示脚本最后固定选择第一条，仅用于说明接口位置。
